GRIDE Help

One toolchain in three outlooks - C90, C++11 and Shalimar for Windows and the TMS320C6747

1. The three outlooks

OutlookVersionWhat it is
BlackGRIDE 1.5.0Visual Studio's way: a workspace of several projects, Visual Studio's keys (White's on request)
GreyGRIDE 2.0.0Visual Studio's look with White's run and debug keys; one project at a time
WhiteGRIDE 1.0The simple one: RIDE's own window and its .pro projects

All three drive the same eleven programs, which sit beside GRIDE.exe: c90, cpp11, shalimar and c2s; masm and link for Windows; asm6x, lnk6x, sim6747 and vm6747 for the C6747, with RTS6x. All three read Code Composer Studio 7.4 / 5.5 projects without changing them. Black and Grey also read Visual Studio solutions. GRIDE's Setup installs one outlook at a time.

2. First steps: the example

The example is cppparse, a C++ program in examples\projects\cppparse beside GRIDE.exe. GRIDE builds it with its own cpp11, masm and link, and links it with GRIDE's own C runtime for Windows (lib\grtc.lib and its layers, and GRIDE's kernel32.lib), so neither Visual Studio nor the Windows SDK is needed. Where Visual Studio is installed, Tools > Options > Projects > GRIDE Paths > Windows C runtime can choose Microsoft's CRT instead. Run it with --health ., and it reports on its own sources. Its cppparse.sln opens in Visual Studio as well.

The rest of examples\projects are projects in C, C++ and Shalimar, one with a third-party library, and the CCS samples; showcase holds three projects of several files - three equations solved in Shalimar and in C++, an average in C - that check their own answers, and shalimar-classic eleven single-file Shalimar programs, each with the lines it prints at its end. examples\programs holds single files, and examples\toolchain-demo\demo.ps1 runs all eleven programs from PowerShell. One examples folder serves the three outlooks. White copies both into Documents\GRIDE the first time it starts. All three outlooks read and write one .pro format, White's: a project saved in one opens in the other two.

5. Where things are

  • Installed: %LOCALAPPDATA%\Programs\GRIDE\<outlook> for one user, or C:\Program Files\GRIDE\<outlook> for everyone. The folder holds GRIDE.exe, the programs, include\ (cpp11's headers), lib\ (c90's headers, the runtimes and TI's option tables), docs\ (these pages) and examples\. Settings > Apps > GRIDE removes it.
  • Your settings: one file, %APPDATA%\GRIDE\settings.json, whichever outlook is installed; each keeps its own keys in it and leaves the others'. A file from before - Black's gride.settings.json beside it, White's %USERPROFILE%\GRIDE 1.0\settings.json - is taken in the first time and then removed. White's settings.json beside GRIDE.exe holds the installation's defaults, under yours. In a portable copy, Black and Grey keep the file beside GRIDE.exe when it is there.
  • The toolchain: Black and Grey read one toolchain.json beside GRIDE.exe, with your changes in %APPDATA%\GRIDE\toolchain.json. The file holds settings only; Settings Files says what each entry is, and its format what each field may hold. White finds each program beside itself.
  • From source: each outlook's GRIDE.sln (Visual Studio 2022's format, v143) builds GRIDE.exe and the eleven programs into x64\<Config>. If Visual Studio 2026 offers to retarget to v145, answer Ignore all.

6. References

The Help menu's Language Reference opens C90, C++11 and Shalimar. Toolchain Reference opens MASM / LINK, ASM6x / LNK6x, RTS6747 and VM6747 / SIM6747. These pages point into RIDE 5.17's complete manual, which describes the compilers, the languages and the targets in full. Settings Files explains toolchain.json, settings.json and the .pro project file. GRIDE Design and Development (2.0) is the project's report: GRIDE and its toolchain - the platforms, the languages, the GUI, the compilers, their optimisation, how they were developed and checked, and what is still open.
